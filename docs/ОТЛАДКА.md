# Ошибки порта Zetvl Focus и как их находить

## Главное правило: BE2 глотает исключения молча

`CFG.LOGS` в игре **выключен**. Поэтому штатный `CFG.exceptionStack(ex)` не пишет
ничего, а обработчики вида

```java
catch (IndexOutOfBoundsException ex) {
    if (CFG.LOGS) { CFG.exceptionStack(ex); }
}
```

проглатывают ошибку без следа. Симптом всегда один и тот же: «кнопка не работает».

**Правило для всего кода фокусов:** в `catch` писать только через
`Gdx.app.error("ZetvlFocus", "...", e)` — этот вывод попадает в `logs/be2.log`
всегда, независимо от `CFG.LOGS`.

## Баг «кнопка Фокусы закрывает панель флага, дерево не открывается» (исправлен)

### Симптом

Клик по иконке «Фокусы» закрывает меню флага, панель дерева не появляется.
В логе при этом есть:

```
ZetvlFocus: Focus tree: rus_c (19)      <- конструктор дерева ОТРАБОТАЛ
ZetvlFocus: Дерево фокусов: видимо=false <- но меню невидимо
```

Это противоречие и есть ключ: конструктор запустился (значит
`menus.get(INGAME).set(idx, new Menu_InGame_FocusTree())` дошёл до создания
объекта), но `getVisible()` вернул `false` (значит `set()` упал **после**
создания объекта, иначе `get(idx).setVisible(true)` отработал бы).

### Причина

`MenuManager` регистрировал три панели фокусов так:

```java
this.INGAME_Focus = this.addNextMenuToView(this.INGAME, new Menu_InGame_Focus(0, 0));
this.INGAME_Focus_DECISION = this.addNextMenuToView(this.INGAME, new Menu_InGame_FocusDecision(0, 0, 0));
this.INGAME_FLAG_ACTION_FocusTree = this.addNextMenuToView(this.INGAME, new Menu_InGame_FocusTree());
```

Первый конструктор падал: у цивилизации 0 нет `civFocus`
(`civ.civFocus.list.getFocus(0)` → NPE). Исключение уходило наверх, и
**вторая и третья строки не выполнялись** — индекс
`INGAME_FLAG_ACTION_FocusTree` оставался `-1`.

Дальше каждый клик делал `menus.get(INGAME).get(-1)` →
`IndexOutOfBoundsException` → тишина. Отсюда «дерево не открывается».

Побочный эффект был шире: строки после регистрации фокусов (позиционирование
панелей дипломатии, `Menu_InGame_Report` и т.д.) тоже не выполнялись.

### Исправление

1. `MenuManager.addFocusMenu(int)` — регистрирует панель, ловит `Throwable`
   и при неудаче ставит `Menu_Focus_Empty`, чтобы индекс всегда был валидным.
2. Конструкторы `Menu_InGame_Focus`, `Menu_InGame_FocusDecision`,
   `Menu_InGame_FocusTree` больше не бросают исключений:
   - `findFocus(civID, focusID)` возвращает `null` вместо NPE/выхода за границы;
   - `findCiv(civID)` — то же для цивилизации;
   - `Menu_InGame_FocusTree.playerCivID()` — 0 вместо NPE, когда `CFG.game == null`
     (при регистрации меню игры ещё нет).
3. Все `catch` в фокус-пути `MenuManager` теперь логируют через
   `Gdx.app.error` независимо от `CFG.LOGS`.

Проверка в логе после исправления:

```
ZetvlFocus: Регистрация меню фокусов: INGAME_Focus=87 INGAME_Focus_DECISION=88 INGAME_FLAG_ACTION_FocusTree=89
ZetvlFocus: Клик по кнопке фокусов
ZetvlFocus: Клик: civID=32 тег=rus_c civFocus=фокусов=19
ZetvlFocus: Focus tree: rus_c (19)
ZetvlFocus: Дерево фокусов: видимо=true
```

## Как проверять самому (без игрока)

На машине есть живой X-сервер (`DISPLAY=:0.0`), поэтому игру можно запустить и
управлять ею самому через Java `Robot` (клики + скриншоты), а результат
смотреть в `logs/be2.log` — там видно каждый шаг кода фокусов.

Инструменты: `/tmp/opencode/ui/` (`Ui`, `UiClick`, `UiHover`, `see.py`).
Главный источник правды — лог, а не скриншот: пиксели читать нечем.
